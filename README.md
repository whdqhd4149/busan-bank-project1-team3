# 🏦 부산은행 금융 웹 서비스 - Admin & Customer Web

Spring Boot 기반 금융 웹 서비스 팀 프로젝트입니다.

고객 화면에서는 금융 상품 조회, 투자 성향 분석,
금융 게시물 확인 등의 기능을 제공하고,

관리자(Admin) 화면에서는
펀드 상품 데이터 관리,
상품 상세 조회,
가입 및 결재 처리 흐름 등을 관리할 수 있도록 구성했습니다.

사용자와 관리자 기능을 분리하여
금융 서비스 운영 흐름을 웹 환경에서 구현한 프로젝트입니다.

화면에서 전달되는 데이터와 서버·DB 데이터 흐름이 연결될 수 있도록 기능을 구현했습니다.

또한 단순 화면 출력이 아니라,
상품 상세 조회 및 게시글 CRUD 기능이 실제 데이터와 연동되어 동작할 수 있도록 처리했습니다.

# 4. 관리자 펀드 상품 상세 조회 기능

관리자 페이지에서 등록된 펀드 상품 목록을 조회하고,
선택한 상품의 상세 정보를 별도 페이지 이동 없이 확인할 수 있도록
모달 기반 상세 조회 기능을 구현했습니다.

기존 관리자 목록 화면 구조를 분석한 뒤,
선택한 상품의 펀드코드를 기준으로 상세 데이터를 조회하도록 처리했으며,
조회된 데이터는 모달 화면에서 출력될 수 있도록 연결했습니다.

또한 상품 기본 정보뿐 아니라:

- 수익률 데이터
- 차트 데이터
- PDF 문서 링크

까지 함께 조회할 수 있도록 처리했습니다.

---

## 처리 흐름

상품 선택  
→ 펀드코드 전달  
→ 상세 조회 요청  
→ 서버 데이터 조회  
→ 모달 데이터 출력

---

## 구현 내용

- 펀드 상품 목록 조회 기능 구현
- 펀드코드 기반 상세 데이터 조회 처리
- 상세 조회 모달 데이터 연동
- 수익률 및 차트 데이터 조회 처리
- PDF 문서 링크 조회 기능 구현

# 5. 금융 게시판 관리 기능

관리자 화면에서 정보공시, 수시공시, 펀드시황,
가이드 및 펀드정보 게시판을 관리할 수 있도록
게시글 CRUD 기능을 구현했습니다.

게시글 데이터가 DB와 연결되어
등록·수정·삭제 이후 목록에 반영될 수 있도록 처리했으며,
게시판 유형에 따라 데이터를 구분하여 조회할 수 있도록 구성했습니다.

또한 게시글 목록이 많아지는 상황을 고려하여
페이지네이션 기능을 적용했습니다.

---

## 처리 흐름

게시글 작성  
→ 서버 요청 전달  
→ DB 저장 및 수정 처리  
→ 게시글 목록 조회  
→ 관리자 화면 출력

---

## 구현 내용

- 게시글 등록 / 조회 / 수정 / 삭제 기능 구현
- 게시판 유형별 데이터 조회 기능 구현
- 페이지네이션 처리
- 관리자 화면과 DB 데이터 흐름 연결

# 6. 문제 해결 경험 (Troubleshooting)

## PDF 문서 조회 404 오류 해결

펀드 상세 조회 기능 구현 과정에서
약관·투자설명서·간이투자설명서 PDF 문서를 연결하는 작업을 진행했습니다.

초기 테스트 단계에서는 DB에 임의의 문서 데이터를 등록하여 확인했지만,
이후 실제 서버에 저장된 문서를 불러오는 과정에서
PDF 조회 시 404 오류가 발생했습니다.

문제 원인을 확인하기 위해:

- 화면에서 생성되는 링크
- JavaScript 요청 경로
- 서버에 저장된 실제 파일명

을 순서대로 비교하며 데이터 흐름을 확인했습니다.

그 과정에서 JavaScript에서 요청하는 경로명과
실제 서버에 저장된 파일명이 서로 다르다는 점을 확인했습니다.

- 기존: {펀드코드}_terms.pdf
- 수정: {펀드코드}_약관.pdf

처럼 요청 URL과 실제 저장 파일 규칙이 서로 달라
문서 조회가 정상적으로 이루어지지 않았습니다.

이후 JavaScript 요청 경로와 서버 저장 파일 규칙을 동일하게 수정하여
PDF 문서가 정상적으로 조회될 수 있도록 처리했습니다.

---

## 배운 점

이번 문제 해결 과정을 통해
단순히 화면 기능만 구현하는 것이 아니라,

- 화면 요청
- JavaScript 처리
- 서버 경로
- 실제 저장 파일

까지 전체 데이터 흐름을 단계적으로 확인하는 과정이 중요하다는 점을 경험했습니다.

---

# 7. 프로젝트를 통해 배운 점 (What I Learned)

프로젝트를 진행하며
관리자 기능 구현 과정에서 CRUD 흐름과 데이터 조회 구조를 직접 연결해보며,
화면과 서버, DB 간 데이터 흐름이 어떻게 이어지는지 이해할 수 있었습니다.

또한 단순히 기능 구현만 하는 것이 아니라,
실제 데이터가 어떤 흐름으로 전달되고 처리되는지 확인하는 과정의 중요성을 경험했습니다.

특히 PDF 문서 조회 오류를 해결하는 과정에서는
JavaScript 요청 경로와 서버 파일 규칙을 직접 비교하며
문제 원인을 단계적으로 추적했고,

이 경험을 통해
문제가 발생했을 때 데이터 흐름을 기준으로 원인을 확인하는 습관의 중요성을 배울 수 있었습니다.
